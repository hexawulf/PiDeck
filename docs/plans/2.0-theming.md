## Root cause (verified)
The app paints with `--pi-*` variables (352 `pi-*` uses in 11 files, all via tailwind.config.ts:55-65
or the `.pi-*` helpers), but `--pi-*` is defined ONLY in `:root` with DARK values. Toggling `.dark`
changes only the shadcn tokens (inputs, outline buttons) -> "just a light border around boxes".
Also: ~80 hardcoded dark-tuned classes (text-white x23, text-gray-400 x35, text-{red,green,yellow}-400,
border-gray-800), 6 hex literals in resource-graphs.tsx, `.status-*` classes, and a toggle bug when the
stored theme is "system" (dashboard.tsx:107).

## Data flow
```
 localStorage("pideck-ui-theme")   prefers-color-scheme
            │                              │
            ▼                              ▼
  index.html <head> inline script ──► <html class="dark|light">  (sole resolver on LOAD)
                                           │ read once
                                           ▼
  ThemeProvider: state from <html> class; handles clicks + OS 'change' (sole resolver at RUNTIME)
            │
            ▼
  index.css  :root{--pi-* LIGHT}  .dark{--pi-* DARK}  color-scheme: light|dark
   ├─ bg-pi-* / .pi-* helpers   (352 uses, 0 component edits)
   ├─ .status-* → var(--pi-success|warning|error[-soft])
   ├─ Recharts stroke/stopColor="var(--pi-chart-N)"   (no hook, no re-render)
   └─ ~80 hardcoded classes → pi-* tokens (per-hit review; text-white on accent stays)
```

## Toggle state machine (decision 1A)
```
 stored: none|"system" ──► resolved = OS ──(OS change)──► resolved = OS'
        │ click                                      
        ▼                                             
 stored: opposite(resolved) ("light"|"dark")  ──(OS change)──► ignored
        │ click
        └──► stored: opposite
```
Default for new visitors: system (App.tsx defaultTheme "dark" → "system").

## As built (2026-09-21) — deviations from the plan above
- E2E port is **5017** (5007 is PiTasker prod); `reuseExistingServer: false`.
- CSP hash is **computed at server startup** from the served index.html (server/security.ts),
  not hardcoded — no drift possible. connect-src is `self` only (no WebSockets in client).
- Issue 5A: env/file password checked before the DB (server/services/env-password.ts) so
  E2E/bootstrap logins never hit the admin lockout counter.
- E2E login uses a throwaway password in `.e2e/password` via APP_PASSWORD_FILE (not a DB user;
  PiDeck is single-admin).
- axe found 1.x dark-palette contrast failures → dark accent blue-500→600, dark error → red-400,
  terminal muted → gray-400. The 1.x password-autofill hack was removed (it made dark inputs unreadable
  once --pi-input existed).
- Undefined tokens used in 1.x (`pi-input`, `pi-accent-hover`, `text-pi-muted`) are now defined/remapped.
- Installs require `--legacy-peer-deps` (pre-existing vite 8 vs @vitejs/plugin-react 4.7 peer range).
